Two real workflows

Each tool reduces a different kind of uncertainty.

01 · CRS CALCULATOR

From profile facts to a traceable score

  1. Capture age, education, language, work, and relationship inputs.
  2. Normalize selections to versioned score-table keys.
  3. Evaluate independent factor groups and transferability combinations.
  4. Show the total beside the contribution of each group.
  5. Invite one-input-at-a-time scenario testing.

UX decision: inputs stay visible after calculation so a visitor can explain why the score moved.

02 · CITY COMPARISON

From rankings to explicit trade-offs

  1. Select two destinations from a versioned city dataset.
  2. Align cost, housing, climate, transit, and opportunity dimensions.
  3. Normalize unlike units for visual comparison without hiding raw values.
  4. Place advantages and constraints side by side.
  5. Turn “best city” into “best compromise for this priority.”

UX decision: no opaque winner is produced; the user owns the weighting and final judgment.

CRS FACTOR ENGINE · PRIVATE-PRODUCT PSEUDOCODE
profile = validate(form_values)
base = score_table.lookup(profile.core_factors)
language = score_language(profile.tests)
transfer = cap(score_transferability(profile), table.max)
return explain(base + language + transfer)

This describes the flow and boundaries; it is not copied from the private repository.

CITY COMPARISON · PRIVATE-PRODUCT PSEUDOCODE
left, right = cities.require(selected_ids)
dimensions = schema.comparable_fields
return dimensions.map(field => ({
  raw: [left[field], right[field]],
  normalized: normalize(field)
}))

Raw values stay available beside normalized presentation so the UI does not manufacture certainty.

Source update workflow

Numbers carry provenance and effective dates.

  1. 01 · Monitor

    Track official rule/table changes and scheduled dataset reviews.

  2. 02 · Stage

    Update a new version with source URL, retrieval date, effective date, and notes.

  3. 03 · Validate

    Run schema, range, boundary, and known-scenario fixtures before activation.

  4. 04 · Review

    Compare representative outputs and editorial explanations against the previous version.

  5. 05 · Release

    Activate the version atomically and retain the old fixture for regression history.

CRS decisions should always be confirmed against current official Canadian sources. The calculator is educational, not legal advice.
